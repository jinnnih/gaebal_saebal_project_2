# 개발새발 프로젝트 2 — 택배 분류 허브

포장된 박스를 배송 지역별로 자동 분류하고, AMR 이 트럭 상하차를 맡는 물류 허브 시뮬레이션.
2인 프로젝트. [프로젝트 1(자율 발렛파킹)](https://github.com/jinnnih/gaebal_saebal_project_1) 에 이어진다.

| 항목 | 내용 |
|---|---|
| 환경 | Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic / Nav2 |
| 로봇 | 차동구동 AMR 2~3대 (상하차) · 로봇팔 15개 (분류 · 적재, 연출) |
| 관제 | React + Express + MySQL, rosbridge 연동 |
| 표준 참고 | WCS (Warehouse Control System) 구조 |

## 시나리오

### 무대

```
[입고 트럭] ─하차─▶ [입고 레일] ─▶ 팔① ─▶ 팔②③ ─▶ 팔④⑤⑥⑦ ─▶ 레일 L1~L8
    ▲                                                            │
   AMR                                                        적재 팔
                                                                 │
[지역 트럭 도크 ×8] ◀──────────── 상차 ──────────────────────── AMR
```

- **분류기 7개** — 로봇팔. 박스의 목적지를 읽고 좌/우 레일로 넘긴다. 1 → 2 → 4 → 8 로 갈라진다
  (서울/부산 → 강북/강남·동/서 → 구역)
- **최종 레일 8개** — 배송 지역 8곳. 레일 끝마다 적재 팔 하나
- **AMR 2~3대** — 트럭에서 내리고(하차), 트럭에 싣는(상차) 일
- **도크** — 입고 트럭 도크 1, 지역 트럭 도크 8

### 박스 하나의 여정

1. 입고 트럭 도착 → 서버가 AMR 에 **하차** 배차 → AMR 이 박스를 입고 레일로
2. 사람이 박스를 팔① 레일에 올림 (시뮬에서는 스폰). 박스에는 목적지가 있다
3. 팔① 이 읽고 부산 → 오른쪽. 팔③ 이 읽고 부산 서 → 오른쪽. 팔⑦ 이 읽고 → L7
4. L7 에 박스가 쌓인다
5. 5개가 되거나 3분이 지나면 서버가 AMR 에 **상차** 배차
6. AMR 이 L7 앞에 정밀 정차 → 적재 팔이 박스를 올림 → 부산 서 도크로 → 내림 → 복귀

### 서버가 풀어야 하는 것

| 상황 | 판단 |
|---|---|
| 두 주문이 동시에 | AMR 2대에 나눔 |
| 같은 레일에 두 AMR | 먼저 온 쪽이 레일을 잠금 |
| AMR 이 모자람 | 일을 줄에 세우고 AMR 이 비면 줄 앞부터 |
| 하차와 상차가 같이 | 하차 먼저 — 트럭을 세워두면 안 된다 |
| AMR 고장 | 일을 다른 AMR 에 넘김 |
| 배터리 부족 | 지금 일 마치고 충전소로 |
| 긴급 정지 | 전 AMR 즉시 정지 |

## 역할

| 브랜치 | 담당 | 범위 |
|---|---|---|
| `ks` | moon | AMR 모델, Nav2, Gazebo 월드(레일·팔·도크), 팔 동작 재생 |
| `hj` | zeenee | 관제 서버(배차 · 레일 추적 · 락), 관제 화면, 로봇 화면, DB |
| `main` | — | 공통 문서와 설정. 마지막에 통합 |

### 두 파트가 만나는 지점

- **박스 정보** — 서버가 스폰 시 ID 와 목적지를 기록. 분류기는 서버에 물어 좌/우를 정한다
- **토픽 계약** — 프로젝트 1 의 #9 방식 그대로. 노드 구현 전에 스키마와 QoS 를 이슈로 고정한다
- **레이아웃 원본** — 레일 · 도크 · 충전소 좌표는 `ros/` 의 JSON 하나가 원본. DB 에 복사하지 않고 체크섬으로 재생성을 감지한다
